How the code works, part by part

Portrait Studio takes one photo of a person, lets the user pick a scene (for example Office), and generates that person placed into the scene — same face, new setting — using Google's google/gemini-3.1-flash-image model through OpenRouter. This page explains every part of the project and how a request travels through it.

05 Style registry — src/lib/styles.ts

Styles are data, not code. Each entry in the STYLES array is a StyleDefinition: an id, display fields (name, tagline, emoji, gradient), and a prompt — the exact instruction sent to the model.

Every prompt starts with the scene description, then appends one shared block, IDENTITY_PRESERVATION, which is the product's core contract:

// excerpt from styles.ts
const IDENTITY_PRESERVATION =
  "Keep the person's face, features, hairstyle… exactly identical… " +
  "Integrate them seamlessly: match the scene's lighting direction, " +
  "color temperature, shadows, perspective, depth of field…";

export const STYLES = [
  { id: "office", name: "Office", prompt:
    "Place the person from the photo into a bright, modern executive office… " +
    IDENTITY_PRESERVATION },
  /* beach, cafe, studio, nightscape, alpine … */
];

The Office prompt additionally describes camera language (85 mm, f/2.8, window light) — concrete photographic direction consistently produces more believable composites. The picker UI and the API's valid-style list both derive from this array, so adding an entry is all it takes to ship a new scene.

06 API contract — src/lib/api.ts

This module is imported by both the browser and the server, which is what prevents client/server drift:

  • GenerateRequest — { image, styleId }
  • GenerateResponse — success { ok: true, image, note? } or failure { ok: false, error, code }
  • ERROR_CODES / ErrorCode — the seven stable error codes both sides understand
  • STYLE_IDS — derived from the registry with STYLES.map(s => s.id), so it can never go stale

07 API route — src/app/api/generate/route.ts

The single server endpoint. Its POST handler runs four gates in order:

Gate 1 — rate limit

checkRateLimit(clientKey(request.headers)). Blocked callers get 429 plus a Retry-After header.

Gate 2 — body ceiling

Content-Length over 14 MB returns 413 before the body is even read — cheap protection against memory abuse.

Gate 3 — schema validation

A zod schema enforces the data-URL format, decodes the base64 to measure real bytes (base64ToBytes accounts for padding and newlines), and checks the style id. Failures map to 400 or 413.

Gate 4 — generation

Resolves the style from the registry and calls generateStyledImage({ imageDataUrl, prompt: style.prompt, signal: request.signal }). Passing request.signal means a cancelled browser request also cancels the upstream call.

// the happy path, condensed
const style = getStyle(parsed.data.styleId)!;
const result = await generateStyledImage({ imageDataUrl, prompt: style.prompt, signal: request.signal });
return NextResponse.json({ ok: true, image: result.image, note: result.note });

Errors are translated once, here: OpenRouterError.code → HTTP status via STATUS_BY_CODE. Configuration problems (not_configured) log the technical detail server-side and return a sanitized message, so env-var names never reach end users.

08 OpenRouter client — src/lib/openrouter.ts

A dependency-free fetch wrapper (no SDK needed). Everything it does is visible in one function, generateStyledImage(): 

fetch(`${baseUrl}/chat/completions`, {
  headers: {
    Authorization: `Bearer ${process.env.OPENROUTER_API_KEY}`,
    "HTTP-Referer": process.env.APP_URL,   // OpenRouter attribution
  },
  body: JSON.stringify({
    model: process.env.OPENROUTER_IMAGE_MODEL ?? "google/gemini-3.1-flash-image",
    modalities: ["image", "text"],        // ask for image output
    messages: [{
      role: "user",
      content: [
        { type: "text",  text: prompt },                // the style instruction
        { type: "image_url", image_url: { url: imageDataUrl } }, // the user's photo
      ],
    }],
  }),
  signal: AbortSignal.any([requestSignal, AbortSignal.timeout(120_000)]),
})

Key behaviors:

  • Model selection defaults to google/gemini-3.1-flash-image ( Nano Banana 2), overridable via OPENROUTER_IMAGE_MODEL — useful for testing against google/gemini-3-pro-image or future models.
  • Timeout & cancellation: both the caller's signal and a 120 s deadline are combined; races are caught and re-thrown as typed errors (timeout, upstream_error).
  • Typed failures: every failure path throws OpenRouterError carrying a machine-readable code and a user-safe message. Upstream 401/402/403 → not_configured, 429 → rate_limited, and so on.
  • No-image responses: if the model answers with text but no image (usually a content refusal), the note is surfaced so the user knows why.

09 Rate limiting — src/lib/rate-limit.ts

A fixed-window limiter: per client, at most RATE_LIMIT_MAX_REQUESTS (8) accepted requests per RATE_LIMIT_WINDOW_MS (60 s). Timestamps live in a Map; a periodic sweep evicts empty buckets so memory can't grow unbounded.

It is deliberately in-memory — zero dependencies, perfect for a single instance. The module exposes exactly two functions (checkRateLimit, clientKey), so swapping the internals for Redis or an edge limiter when scaling horizontally is a one-file change.

10 Browser image prep — src/lib/image-client.ts

The browser does the heavy lifting before any bytes hit the network:

  1. Validate — MIME type must be PNG/JPEG/WebP; source file ≤ 25 MB. Violations throw InvalidImageError with a friendly message.
  2. Downscale if needed — anything above 2048 px (or over the 10 MB wire limit) is drawn onto a canvas at reduced scale and re-encoded (JPEG q0.9; PNG keeps its format for transparency) via createImageBitmap.
  3. Fall back safely — if canvas re-encoding fails (rare browser quirks), the original data URL is returned and the server's identical limits act as the net.

This keeps requests small and fast, and it means the server-side size limits are a safety net rather than the everyday path. The module also provides downloadDataUrl(), which powers the result's Download button.

11 UI components

components/ImageStudio.tsxclient
The orchestrator. Holds photo, styleId, and a four-state machine (idle → generating → done | error). It owns an AbortController in a ref so starting a new generation (or unmounting) cancels the in-flight one. Numbered step sections guide the user; the Generate button stays disabled until a photo exists.
components/ImageUploader.tsxclient
Three input paths: drag & drop (with hover highlight), the native file picker, and a global paste listener for screenshots. Once a photo is set it shows a preview with Replace / Remove. All files flow through prepareImageFile().
components/StylePicker.tsxclient
Renders STYLES as an accessible radiogroup of cards (role="radio", aria-checked). Contains no style data of its own — it maps the registry, so UI and API can never disagree.
components/ResultPanel.tsxclient
Renders the four states: an empty placeholder, a shimmering "generating" card, a friendly error card, or the result image with Download (via downloadDataUrl) and Copy (clipboard) actions.
app/page.tsx + app/layout.tsxserver
layout.tsx loads the Geist fonts, sets metadata, and wraps everything; page.tsx renders the hero and mounts <ImageStudio />. The ambient page glow and shimmer keyframes live in globals.css (Tailwind v4 theme).

12 Error handling map

Every failure becomes one of seven stable codes, shared by both sides through api.ts:

CodeHTTPWhen it happensUser sees
bad_request400Malformed JSON, not a data URL, unknown styleExact reason
too_large413Image over 10 MB decoded / 14 MB body"Image is too large."
rate_limited429More than 8 requests/min from one IP (also from OpenRouter itself)Retry message + Retry-After
not_configured503Missing/invalid API key or out of creditsSanitized message; detail only in server logs
upstream_error502OpenRouter unreachable or 5xx"Something went wrong…"
upstream_refused502Model answered with text, no image (e.g. safety refusal)The model's own explanation
timeout504Upstream exceeded 120 s"Generation timed out…"
🔒 Security posture: the OpenRouter key is server-only; uploads are type-checked twice (client and server) so scripts or HTML can never masquerade as images; response headers set X-Content-Type-Options, X-Frame-Options: DENY, Referrer-Policy, and a Permissions-Policy that disables camera/mic/geolocation.

13 How to add a new style

No UI or API changes are needed — append one object to STYLES in src/lib/styles.ts:

{
  id: "gym",                      // stable, unique, used in the API
  name: "Gym",                    // card title
  tagline: "Mid-workout, weights in hand",
  emoji: "🏋️",
  gradient: "from-lime-400/80 to-emerald-600/80",
  prompt: "Place the person from the photo in a modern gym… " + IDENTITY_PRESERVATION,
}

Everything else updates automatically: the picker card, the API's valid styleId list (derived), the "Generate … scene" button label, and the download filename.
